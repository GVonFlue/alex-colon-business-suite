YOU WERE RIGHT, AND IT WAS WORSE THAN THE TASK SCREEN
--------------------------------------------------------------------------

A bare <input> in this CRM got NOTHING from the stylesheet.

Every input rule in styles.js is scoped -- .field input, .gate-card input,
.cp-add input -- so anything rendered as a plain <Inp /> fell all the way back
to the browser's default control. No padding, no radius, no border colour, no
focus ring.

THAT IS 118 INPUTS ACROSS NINE VIEWS. Books, Contacts, Contracts, Huddle, PCS,
Settings, Tasks, Tools, Transactions. The task screen is simply where it was
visible sitting next to a styled product.

ProyTech does not have this problem because it styles that input INLINE, in
the component, rather than relying on the stylesheet.

FIXED GLOBALLY, not on the one box. There is now a baseline rule for input,
select and textarea at ONE specificity (0,0,1), so every existing scoped rule
still wins and nothing that already looked right changes. Verified: all 14
tabs still render, no NaN, no undefined, 661 checks pass.

The add row then runs LARGER than that baseline -- 46px tall, 11px radius,
14.5px type -- because it is the one control in the product somebody touches
every single day and it should be the easiest thing on the screen to hit. The
day chips and the Add button are pinned to the same height, or a 46px field
beside a 36px button reads as misaligned even when it is centred.
