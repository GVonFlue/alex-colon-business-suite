THE BLANK CONTACTS
--------------------------------------------------------------------------

src/views/Contacts.jsx rendered the areas-of-interest chips like this:

    {(d.areas || []).map(a => ...)}

That guards null and nothing else. A contact whose `areas` arrived as a
STRING hits .map on a string, throws, and React unmounts the entire tree.
White page.

WHERE THE STRINGS CAME FROM: the demo-data SQL I gave you for the Cowork
screenshots. Seven of those rows carry

    'areas', 'Maize, Goddard'

as a string, because that is how I wrote it. The UI stores an array. That is
why SOME contacts opened and some did not — only the seeded ones with areas
are broken, and they are broken because of my file.

Fixed in src/lib/areas.js, a normaliser that takes an array, a comma string, a
single value, null or undefined and always returns an array. Applied on the
READ path and the WRITE path both: spreading a string would have exploded
"Maize" into five separate chips.

It lives in lib rather than in the component because it is data normalisation
rather than UI, and because a .jsx file cannot be imported by the test runner —
which is the other half of why this was never caught.

WHY 661 CHECKS PASSED WHILE THIS WAS BROKEN: the tab walker clicks TABS. This
only happens when a RECORD opens. tests/contactopen.test.mjs now opens 25
contact records and asserts none of them render blank, plus eight shape cases
on the normaliser itself.

671 checks pass.
